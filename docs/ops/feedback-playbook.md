# External feedback operating policy

This document owns Gitwink-specific response and escalation decisions. Collection state belongs to `feedback-ops`, while implementation work promoted from a confirmed case belongs to GitHub.

## Sources

- GitHub issues, pull requests, issue comments, and review comments are collected as external feedback evidence. Collection alone never opens another issue or creates a case.
- Microsoft Store reviews are collected read-only. Responses remain manual until the provider response path is separately proven.

## Triage

Prioritize reproducible data-loss or repository-corruption reports, install/update failures, and repeated workflow blockers. Keep praise, one-off questions, and non-actionable comments in the inbox without turning every item into backlog.

When multiple people report the same behavior, keep every original item and attach them to one case. An issue may be created only after explicit operator promotion; automatic GitHub promotion and provider replies are disabled in v1.
